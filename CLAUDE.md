# Backup Assurance for Claude Code

A trusted service team owns this evidence database. Read README.md and docs/operations.md before acting. One CLI, scripts/assurance.mjs, owns every recurring read and write. Read the matching .claude/commands recipe, run it and answer from its output.

Start a daily review with morning-check, missing-results and restore-due. A weekly review combines morning-check, restore-due and attention. Use history for one job, client-health for counts, actions for follow-up and compliance for sourced evidence checks. All reads support --json. Every write needs --actor and confirmed record identity. Run help for flags.

Do not send messages, notifications or email. Draft only to drafts. Never claim the live backup engine, collector or pager has been replaced. A stored success does not prove a restore works. Obtain evidence from the operator before logging results or restore tests. Do not read, print or commit credentials. Never commit client exports or real client names.

Codes and partial ids must resolve to one record. If ambiguous, show candidates and resolve before writing. Dates use ISO notation, times require a timezone and output uses UTC. Report cutoffs use current policy, not reconstructed historical policy. Imported vendor daily assessments remain distinct from local checks. Set imported job policies explicitly rather than inferring them.

Use customise for changes: a new numbered migration, updated CLI, command recipe, import mapping and tests. Test on disposable data, then apply within the operator's request. Keep PostgreSQL and PGlite compatible. Never build a writeable front end. Keep renderers shared with the rebuild template. Run npm test before committing on main. End authored commits with Agent: omni-rebuild-strategist.

Voice is plain and specific. No em dashes or inflated claims. Read docs/compliance.md when explaining a rule. Rule results prompt review and do not certify compliance.
